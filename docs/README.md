# docs

This directory holds durable project knowledge. Keep the root files concise
and link here for detail.

## Navigation

| Area | Purpose |
| --- | --- |
| `PRD/` | Problem, users, scope, architecture, and technology rationale |
| `specs/` | Implementation-facing contracts, plans, and visual references |
| `engineering/` | Repository, coding, testing, security, and workflow conventions |
| `planning/` | Roadmaps, milestones, and release preparation |
| `knowledge/` | Risks, assumptions, debt, research, lessons, and future ideas |
| `checklists/` | Phase, feature, release, and operational completion gates |
| `journal/` | Dated records of meaningful work and decisions |
| `reviews/` | Durable independent review findings and resolutions |

Create only documents that have a clear owner and decision-making purpose.
Cross-reference source material instead of copying it. Mark facts,
hypotheses, proposals, and implemented behaviour distinctly.
